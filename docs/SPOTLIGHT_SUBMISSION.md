# 此在 Current · Spotlight 提交说明

这份文档保留赛事评审需要的完整回答。产品介绍、运行方式和当前能力请先看仓库根目录的 [README](../README.md)。

## 1. 我们希望建立什么新品类？

我们把它称为“情绪空间 Agent”：用户不必先知道地点类别，只需要说出此刻的状态。Agent 负责理解表达、调用真实地图、组织推荐和接住到访反馈，把模糊感受转换成一次现实行动。

它不做心理诊断，也不把聊天当作终点。一次任务的完成标准是：用户找到一个真实、可达、此刻愿意去的地方，并且保留纠错和退出的权利。

## 2. 为什么是现在？

这个产品依赖的几项能力最近才开始能够一起工作：语言模型可以处理含混表达；地图服务可以提供真实地点、坐标和路线；手机与穿戴设备能够接续同一次任务；结构化反馈可以帮助我们区分“听起来合理”和“实际去过之后仍然合适”。

但能力可用不代表问题已经解决。目前最难的仍是地点事实、城市差异、弱网语音、推荐评估和隐私边界，这也是我们下一阶段要验证的内容。

## 3. 为什么不是普通地点应用？

普通地点应用通常从类目和筛选条件开始，而用户在情绪低落、疲惫或混乱时，未必能先完成这些判断。Agent 的作用是允许自然语言成为入口，在必要时追问一次，并把模糊表达变成可执行条件。

拿掉 Agent 后，产品仍然可以展示地点列表，但会失去状态理解、动态纠错、工具调度和跨阶段接续；拿掉地图与规则后，它又会退化成只能给建议、无法保证地点真实的聊天机器人。

## 4. Agent 承担什么作用？

- 将自然语言转换为受限的 `NeedState`；
- 在模型调用之前识别高风险表达；
- 根据需求选择地图搜索词和工具；
- 解释推荐依据，并接收“近一点”“安静一点”等纠错；
- 在手机和伴侣端之间维持结构化任务上下文；
- 从到访反馈中提取错配环节，但不把一次反馈当成普遍规律。

地点身份、坐标、路线和最终排序不由模型自由生成。地图负责事实候选，确定性规则负责硬条件和排名，用户可以推翻系统推断。

## 5. 有哪些可运行证据？

公开 Web 原型已支持：

- 文字和语音表达；
- 状态、需要、现实约束和明确活动理解；
- 高风险表达的独立安全路径；
- 高德附近搜索、指定城市搜索和地图路线；
- 1 个主推荐与 2 个备选，以及推荐理由和纠错；
- 到访反馈、私密足迹和分享卡；
- 用户共创、审核与撤回的基础链路；
- 六位临时码的跨设备任务接续原型。

最近一次完整回归包含 208 项后端测试和 67 项前端策略测试。自动化结果不替代真机、真实网络和真实地图服务验收。

## 6. 深圳阶段准备完成什么？

1. 接入至少一款真实智能眼镜，或完成可迁移的设备适配层；
2. 核验一批深圳真实空间的身份、坐标、营业和可达性；
3. 跑通表达、推荐、出发、低打扰陪伴、到达、反馈和回看的跨设备旅程；
4. 把理解错误、地图召回错误、排序错误、事实错误和路线错误分开评估；
5. 进行真实用户测试，记录出发率、有效到访率、后悔率、无结果率和延迟；
6. 验收中国大陆、香港和海外网络下的语音、定位、地图和数据库降级；
7. 与设备方和真实空间讨论一个可执行的 30 天试点。

## 7. 如何扩展？

`NeedState` 和推荐契约可以跨城市复用，地图供应商、地点属性、语言和安全入口按地区替换。中国大陆当前使用高德；海外可以接入 Google Maps、Apple Maps 或当地供应商。

扩展的前提不是一次加入更多城市名称，而是使用 H3／PostGIS 等城市无关空间索引，建立地点来源、核验日期和反馈证据标准，并在每个地区重新验证文化语境与隐私要求。

## 8. 希望获得什么支持？

- 可测试的智能眼镜、SDK 和厂商工程支持；
- GIS／LBS、POI 数据、推荐系统和城市计算专家；
- 深圳本地真实空间、测试用户和线下体验组织；
- 地图、模型、数据库与跨境云服务额度；
- 位置和情绪数据相关的隐私、合规和伦理建议；
- 设备企业、文化空间和城市服务合作渠道。

## 当前边界

- 伴侣网页是跨设备交互原型，不等于已接入真实眼镜；
- 尚未实现 AR 导航、视觉识别和实时步频；
- 地图搜索结果不等于人工核验，事实来源需要分层显示；
- 空间画像机制已经实现，但真实合格到访样本仍然有限；
- 语音在不同浏览器、地区和网络下仍需真机验收；
- 到访后的自报变化不等于医疗或心理学意义上的疗效。

## 我们会如何判断下一版更好？

除了“用户喜不喜欢”，我们会分别看：

- 系统是否正确理解了用户明确表达；
- 地图是否召回了真实、营业且可达的候选；
- 首选是否符合明确活动和硬条件；
- 用户为什么拒绝、换一个或没有出发；
- 到访后是否后悔，以及错配发生在哪个环节；
- p50／p95 延迟、无结果率和外部服务失败率；
- 用户是否理解位置、反馈和共创内容会如何被使用。

把错误拆开，比给推荐系统一个看似漂亮的总分更有助于下一次迭代。
